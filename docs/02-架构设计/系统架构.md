# 系统架构

## 模块划分

```text
Browser
  |
  |  /, /projects/{slug}
  v
Drogon Static Web Server
  |
  |  /api/v1/projects...
  v
ProjectsAction
  |
  v
Storage_SQL -> SQLite(portfolio_projects, site_profile)
```

```text
Update Client / Admin
  |
  |  /api/v1/products...
  v
DocumentAction / CheckUpdateAction / ConvertDataTaskAction
  |
  v
Storage_SQL -> SQLite(products, releases, assets, channels, tasks)
```

## 运行时组件

1. `src/bin/main.cpp`
   - 加载 Drogon 配置。
   - 设置 `web/dist` 为静态站点根目录。
   - 映射 `/data/...` 静态资源。
   - 注册 API 路由。
   - 未匹配前端路径回退到 `index.html`。

2. `src/service`
   - 负责注册 HTTP 路由。
   - 作品集路由在 `register_projects_routes.cc`。

3. `src/action`
   - 负责业务响应组装。
   - `ProjectsAction` 服务 Web 作品集。
   - `DocumentAction`、`CheckUpdateAction`、`ConvertDataTaskAction` 服务更新平台。

4. `src/storage`
   - 负责 SQLite 初始化、迁移补齐和查询。
   - `getPortfolioProjects.cc` 查询作品集列表和详情。

5. `web`
   - Vite + TypeScript 静态前端。
   - 使用 `/api/v1/projects` 渲染首页。
   - 使用 `/api/v1/projects/{slug}` 渲染详情页。

## 数据边界

作品集展示数据：

```text
site_profile
portfolio_projects
```

软件更新数据：

```text
products
releases
release_assets
release_channels
update_packages
convert_rules
convert_tasks
```

`portfolio_projects.product_id` 可选关联 `products.id`。该关联只用于表达“某个作品集案例对应一个真实可更新软件产品”，不影响作品集本身展示。

## 路由边界

作品集：

```http
GET /api/v1/projects
GET /api/v1/projects/{slug}
```

更新平台：

```http
GET /api/v1/products/{product_code}/document
GET /api/v1/products/{product_code}/releases
GET /api/v1/products/{product_code}/check-update/{version}
POST /api/v1/products/{product_code}/convert-tasks
GET /api/v1/products/{product_code}/convert-tasks/{task_id}/status
GET /api/v1/products/{product_code}/convert-tasks/{task_id}/result
```
