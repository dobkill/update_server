# 系统架构

## 架构图

```text
Browser / Client
        |
        v
    Drogon HTTP
        |
        v
  Router::ApiRoutes
        |
        v
      Action
        |
        +----------------+
        |                |
        v                v
   Storage_SQL      Convert Worker
        |                |
        v                v
 SQLite / data   python/convert/convert_data.py
```

## 启动流程

`src/bin/main.cpp`：

1. 查找 `config/drogon_config.json`、`web/dist`、`data`。
2. 初始化 `Config::AppConfig`。
3. 加载 Drogon 配置。
4. 设置 `web/dist` 为静态资源根目录。
5. 调用 `Router::ApiRoutes::Instance()` 注册 API。
6. 设置 `/data/...` 静态文件访问。
7. 设置 SPA fallback。
8. 调用 `app.run()`。

## service 层

`src/service` 路由文件：

1. `register_portfolio_home_routes.cc`
2. `register_products_routes.cc`
3. `register_document_routes.cc`
4. `register_release_routes.cc`
5. `register_check_update_routes.cc`
6. `register_convert_task_routes.cc`
7. `register_convert_task_status_routes.cc`
8. `register_convert_task_result_routes.cc`

service 层只处理 HTTP 输入输出。

## action 层

Action 类：

1. `ProductsAction`
2. `DocumentAction`
3. `CheckUpdateAction`
4. `ConvertDataTaskAction`

`ProductsAction` 提供首页聚合接口和产品列表接口。

`ConvertDataTaskAction` 在构造时创建 worker 线程。任务创建后写入 `convert_tasks`，再由 worker 调用转换脚本。

## storage 层

`Storage_SQL` 职责：

1. 使用 sqlite3 prepared statement。
2. 查询结果返回 `nlohmann::json`。
3. 打开 `config/app.json` 中的 `database_path`。
4. 空库执行 `migrations/002.init.sql`。
5. 已有库执行 `ensurePortfolioSchema()`。
6. 提供首页、版本、更新、转换任务所需查询。
