# 系统架构

## 当前架构

```text
Browser / Client
        |
        v
    Drogon HTTP
        |
        v
  Router::ApiRoutes
        |
        v
      Action
        |
        +----------+
        |          |
        v          v
   Storage_SQL   Convert Worker
        |          |
        v          v
 SQLite/data   python/convert/convert_data.py
```

## 启动流程

`src/bin/main.cpp` 当前启动流程如下：

1. 查找 `config/drogon_config.json`、`web/dist` 等项目路径。
2. 初始化 `Config::AppConfig`。
3. 加载 Drogon 配置。
4. 设置 `web/dist` 为静态资源根目录。
5. 调用 `Router::ApiRoutes::Instance()` 注册 API。
6. 设置 SPA fallback，未知路径回退到 `web/dist/index.html`。
7. 调用 `app.run()`。

## service 层

`src/service` 当前通过 `ApiRoutes` 单例集中注册路由：

1. `register_products_routes.cc`
2. `register_document_routes.cc`
3. `register_release_routes.cc`
4. `register_check_update_routes.cc`
5. `register_convert_task_routes.cc`
6. `register_convert_task_status_routes.cc`
7. `register_convert_task_result_routes.cc`

service 层只做 HTTP 相关工作：读取 path/query/body，调用 action，序列化 JSON 响应。

## action 层

当前 action 类：

1. `ProductsAction`：产品列表。
2. `DocumentAction`：版本详情文档和版本列表。
3. `CheckUpdateAction`：客户端更新检查。
4. `ConvertDataTaskAction`：转换任务创建、排队、执行、状态与结果查询。

`ConvertDataTaskAction` 在构造时创建 worker 线程。创建任务时会保存上传内容、写入 `convert_tasks`，再由 worker 调用转换脚本。

## storage 层

`Storage_SQL` 是当前唯一 SQLite 访问入口：

1. 使用原生 `sqlite3_prepare_v2`、`sqlite3_bind_text`、`sqlite3_step`。
2. 查询返回 `nlohmann::json`，不返回 Drogon 类型。
3. 启动时打开 `config/app.json` 中的 `database_path`。
4. 数据库为空或缺少 `products` 表时执行 `migrations/002.init.sql`。

## 运行时目录

```text
data/
├── database/update_platform.db
├── uploads/convert/
├── converted/
├── failed/
├── packages/
├── releases/
└── logs/
```

这些目录由 `config/app.json` 管理，转换任务会使用 `uploads/convert` 和 `converted`。
