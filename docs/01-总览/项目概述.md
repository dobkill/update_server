# 项目概述

## 1. 项目目标

建设一个以软件更新为核心、同时支持动态页面展示与数据转换的平台，重点解决三类问题：

1. 客户端查询版本、下载更新包、查看历史版本。
2. 用户上传旧数据后，按目标版本完成格式转换并下载结果。
3. 管理员在不停服前提下人工执行 `python/` 下脚本，更新 SQLite 元数据和 `data/` 目录内容。

## 2. 模块总览

平台按六个主模块组织：

1. `web`：Vue 页面、页面运行时、区块组件库。
2. `service`：API 入口、参数校验、响应协议。
3. `action`：业务编排、更新检查、任务流转和在线脚本调度。
4. `storage`：面向 `service/action` 的 SQLite 访问、文件存储、事务与原子替换。
5. `scripts`：以 Python 脚本为主的数据转换脚本和离线管理脚本，当前物理目录为 `python/`。
6. `config`：全局配置与路径约束。

## 3. 依赖原则

依赖关系必须保持单向：

```text
web -> service -> action -> storage
                      |
                      -> scripts
config -> all modules
```

说明如下：

1. `web` 只依赖接口，不依赖数据库和脚本。
2. `service` 只承接协议层，不直接承担完整业务。
3. `action` 是后端流程中心，负责调度 `storage` 与 `scripts`。
4. `storage` 与 `scripts` 不反向依赖上层模块。

## 4. 使用者定义

| 使用者 | 职责 |
| --- | --- |
| 普通访问者 | 浏览站点介绍、文档、下载信息 |
| 软件客户端 | 调用更新接口、提交转换任务、下载结果 |
| 管理员 | 在服务器本机人工执行 `python/` 下脚本，直接维护 `data/` 目录和 SQLite 元数据 |
