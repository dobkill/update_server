# 开发计划与 MVP

## 1. 当前阶段

截至 2026-05-23，项目已完成以下事项：

1. 明确新的六模块设计。
2. 完成 `web` 模块独立实现。
3. 清空旧后端代码，保留新的占位骨架。
4. 重写设计文档与目录结构。

## 2. 新的实施顺序

### 阶段一：固化边界

1. 先固定 `web / service / action / storage / scripts / config`。
2. 保证依赖方向不再反复变化。

### 阶段二：实现 config + storage

1. 先固化配置加载、依赖注入和运行参数。
2. 封装 SQLite 访问。
3. 封装 `data/` 目录操作。
4. 建立事务与原子替换机制。

### 阶段三：实现 action + service

1. 先补产品列表、历史版本列表和版本文档接口。
2. 再补更新检查接口和下载接口。
3. 最后补转换任务接口。

### 阶段四：接通 scripts

1. 接入数据转换脚本。
2. 接入在线转换所需的后台脚本执行链路。
3. 发布、回滚、下线和清理继续保留为管理员人工执行的 `python/` 脚本，不纳入 `service` API。

## 3. MVP 建议

新的最小可用版本建议只包含：

1. `web` 动态页面展示。
2. 产品列表接口。
3. `Document` 文档渲染接口。
4. 更新检查接口与全量下载接口。
5. 一个最小转换任务链路。

## 4. 验收标准

1. `web` 在无后端时可展示演示站点，在有后端时可切换到真实接口。
2. `Document` 接口返回的 JSON 可被 `web` 直接渲染。
3. 更新接口能够从 SQLite 元数据中选出最新版本，并通过下载接口定位全量包。
4. 数据转换能完成上传、执行、状态回写和结果地址返回。
