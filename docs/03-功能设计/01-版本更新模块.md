# 版本更新模块

## 当前接口

版本更新相关能力由两个接口组成：

1. `GET /api/v1/products/{product_code}/check-update/{version}`
2. `GET /api/v1/products/{product_code}/document?version=latest&channel=stable`

为了兼容当前 `web/dist` 构建产物，后端同时支持大写路径：

```http
GET /api/v1/products/{product_code}/Document?version=latest&channel=stable
```

## 更新检查流程

```text
client
  -> service/register_check_update_routes.cc
  -> CheckUpdateAction::CheckUpdate()
  -> Storage_SQL::getLatestRelease()
  -> release_channels + releases + release_assets
```

`CheckUpdateAction` 使用 `Tools::canUpgrade()` 比较客户端当前版本和 latest 版本。

## 请求参数

```http
GET /api/v1/products/demo/check-update/1.0.0?platform=windows&arch=x64&package_type=portable&data_schema_version=1
```

| 参数 | 来源 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `product_code` | path | 无 | 产品编码 |
| `version` | path | 无 | 客户端当前软件版本 |
| `platform` | query | `windows` | 平台 |
| `arch` | query | `x64` | 架构 |
| `package_type` | query | `portable` | 包类型 |
| `data_schema_version` | query | 空 | 客户端当前数据结构版本 |

## 返回数据

找到 latest release 时，`data` 包含：

1. `product_code`
2. `product_id`
3. `current_version`
4. `latest_version`
5. `has_update`
6. `package`
7. `data_upgrade`
8. `data_schema_version`
9. `data_convert`

未找到 latest release 时返回业务 `404`：

```json
{
  "code": 404,
  "message": "latest release not found",
  "data": {
    "product_code": "demo"
  }
}
```

## 当前边界

1. 当前没有独立 `DownloadAction`。
2. 下载包地址暂由 `release_assets.file_path` 返回。
3. 增量包表 `update_packages` 已建模，但当前更新检查优先返回全量包信息。
