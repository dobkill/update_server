# 数据转换模块

## 当前能力

数据转换模块由 `ConvertDataTaskAction` 和 `python/convert/convert_data.py` 组成，提供：

1. 创建转换任务。
2. 查询任务状态。
3. 查询任务结果。
4. worker 线程异步执行转换脚本。

## 接口

创建任务：

```http
POST /api/v1/products/{product_code}/convert-tasks?from_version=1&to_version=2
```

查询状态：

```http
GET /api/v1/products/{product_code}/convert-tasks/{task_id}/status
```

查询结果：

```http
GET /api/v1/products/{product_code}/convert-tasks/{task_id}/result
```

## 创建任务流程

```text
service 保存 body 到 upload_task_dir
  -> ConvertDataTaskAction::createTask()
  -> Storage_SQL::getProduct()
  -> Storage_SQL::getConvertRule()
  -> Storage_SQL::addTask()
  -> 内存队列 pending
  -> worker running
  -> python3 convert_data.py
  -> Storage_SQL::updateTaskStatus()
```

## 转换脚本调用

当前 worker 调用方式：

```bash
python3 <script_path> \
  --input <input_file_path> \
  --output <output_file_path> \
  --source-version <from_version> \
  --target-version <to_version>
```

默认脚本为 `config/app.json` 中的 `convert_script`，实际任务优先使用 `convert_rules.script_path`。

## 转换脚本目录结构

`python/convert/` 目录支持按产品分子目录存放各产品专属转换脚本：

```text
python/convert/
├── __init__.py
├── convert_data.py              # 通用入口（C++ 配置指向此文件）
└── <product_code>/              # 各产品专属转换脚本（可选）
    └── convert_v1_to_v2.py      # 例: convert_v1_to_v2.py
```

- `convert_data.py` 作为默认通用入口，C++ worker 线程通过 `config/app.json` 的 `convert_script` 配置指向此文件
- `convert_rules.script_path` 可指向 `python/convert/<product_code>/convert_xxx.py` 实现产品专属转换逻辑
- 管理员可在 TOML 配置中添加 `[[convert_rule]]`，再通过 `python python/admin/admin.py` 统一入口注册到数据库

## 状态

1. `pending`
2. `running`
3. `success`
4. `failed`
5. `canceled`

## 当前边界

1. service 当前把请求 body 作为原始文件内容保存，尚未实现 multipart 文件上传解析。
2. 任务状态同时保存在内存 `task_map` 和 SQLite `convert_tasks`。
3. 进程重启后内存队列不会恢复执行，但状态/结果接口会回退查询 SQLite。
4. 输出文件路径当前直接作为 `download_url` 返回，后续可替换为独立下载接口或签名 URL。
