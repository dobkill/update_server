# 软件更新平台项目设计

## 文档定位

本文档是当前项目设计入口。代码已经从“后端骨架”推进到可构建、可启动、可注册 API 路由的阶段；历史文档仍有参考价值，但后续以当前代码和本文档为准。

## 当前状态

1. `src/bin/main.cpp` 会加载 Drogon 配置、初始化应用配置、注册 `ApiRoutes`，并启动 HTTP 服务。
2. `service` 已注册产品列表、版本文档、版本列表、更新检查、转换任务创建/状态/结果接口。
3. `action` 已形成 `ProductsAction`、`DocumentAction`、`CheckUpdateAction`、`ConvertDataTaskAction` 四个业务入口。
4. `storage` 已使用原生 sqlite3 prepared statement 访问 SQLite，并在数据库为空或缺表时执行 `migrations/002.init.sql`。
5. `web/dist` 会作为静态首页目录；未知前端路由会回退到 `web/dist/index.html`。
6. 数据库当前可能为空，因此接口能正常返回空列表或业务 `404`，不代表服务异常。

## 构建与运行

```bash
cmake --build build -j 2
./build/software_update_platform
```

默认监听 `config/drogon_config.json` 中的 `8080` 端口。

可快速验证：

```bash
curl http://127.0.0.1:8080/api/v1/products
curl "http://127.0.0.1:8080/api/v1/products/demo/check-update/1.0.0?platform=windows&arch=x64&package_type=portable"
```

## 核心原则

1. 依赖方向保持 `web -> service -> action -> storage`，转换任务由 `action -> python/convert` 调度。
2. `service` 只处理 HTTP 路由、参数和响应序列化，不直接访问 SQLite。
3. `action` 负责任务编排、业务判断和统一业务响应。
4. `storage` 只处理 SQLite 查询/写入和迁移初始化，不返回 Drogon 类型。
5. `config/app.json` 管理应用路径，`config/drogon_config.json` 管理 HTTP 服务参数。
