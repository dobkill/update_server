## 核心设计原则

1. 主模块固定为 `web / service / action / storage / scripts / config`。
2. 对外依赖必须单向流动：`web -> service -> action -> storage`，并由 `action -> scripts`。
3. `service` 负责 API 协议与接口入口，不承担完整业务编排。
4. `action` 负责业务用例、状态切换、审计与脚本调度，是后端核心流程层。
5. `storage` 同时管理 `SQLite` 与文件目录，数据库只保存元信息，正式内容保存在 `data/`。
6. 发布、回滚、下线和清理不通过 Web 后台或 HTTP API 执行，而是由管理员在服务器本机人工执行 `python/` 下固定脚本；这些脚本可直接修改 SQLite 和 `data/` 目录。

## 当前仓库状态

1. `web` 模块已实现，可独立运行并使用内置演示页面数据展示内容。
2. 后端源码已清空为占位骨架，便于后续按模块重新实现。
3. `include/` 下已改为直接按模块放置，不再增加 `update_platform/` 这一层目录。
4. 设计文档全部以新的模块边界为准。
