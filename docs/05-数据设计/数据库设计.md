# 数据库设计

## 现状说明

当前数据库结构以 `migrations/002.init.sql` 为准。`Storage_SQL` 在启动时打开 `config/app.json` 中的 `database_path`，当数据库为空或缺少 `products` 表时执行该迁移。

数据库保存元信息、路径、状态和任务记录；实际上传文件、转换结果、安装包和页面资源保存在 `data/`。

## 表结构总览

| 表 | 说明 |
| --- | --- |
| `products` | 产品基础信息 |
| `releases` | 产品逻辑版本 |
| `release_assets` | 某版本的平台/架构/包类型全量包 |
| `release_channels` | stable/beta/dev 等渠道 latest 指针 |
| `update_packages` | 增量包或补丁包 |
| `convert_rules` | 数据结构版本转换规则 |
| `convert_tasks` | 数据转换任务记录 |

## products

关键字段：

1. `id`
2. `name`
3. `code`
4. `description`
5. `icon_path`
6. `status`
7. `created_at`
8. `updated_at`

`ProductsAction` 返回产品列表时会把 `code` 映射为 `product_code`，把 `description` 映射为 `summary`。

## releases

关键字段：

1. `id`
2. `product_id`
3. `version`
4. `release_note`
5. `data_schema_version`
6. `status`
7. `vue_path`
8. `published_at`

`DocumentAction` 查询指定版本时使用 `product_code + version` 定位 `releases`。

## release_assets

关键字段：

1. `product_id`
2. `release_id`
3. `platform`
4. `arch`
5. `package_type`
6. `file_path`
7. `file_size`
8. `sha256`
9. `md5`
10. `status`

更新检查会根据 `release_channels` 指向的 latest release，再关联 `release_assets` 返回包信息。

## release_channels

关键字段：

1. `product_id`
2. `release_id`
3. `channel`
4. `platform`
5. `arch`
6. `package_type`
7. `is_latest`
8. `status`

同一 `product_id + channel + platform + arch + package_type` 在 `status = active` 时只能有一个 `is_latest = 1`。

## convert_rules

关键字段：

1. `product_id`
2. `source_data_schema_version`
3. `target_data_schema_version`
4. `script_path`
5. `cost_time`
6. `script_sha256`
7. `status`

创建转换任务时，`ConvertDataTaskAction` 使用 `product_id + source_data_schema_version + target_data_schema_version` 查找 active 规则。

## convert_tasks

关键字段：

1. `task_id`
2. `product_id`
3. `convert_rule_id`
4. `source_data_schema_version`
5. `target_data_schema_version`
6. `status`
7. `input_file_path`
8. `input_file_sha256`
9. `output_file_path`
10. `output_file_sha256`
11. `retry_count`
12. `created_at`
13. `updated_at`

状态枚举：

1. `pending`
2. `running`
3. `success`
4. `failed`
5. `canceled`

## 文件目录

当前默认配置：

```text
data/
├── database/update_platform.db
├── uploads/convert/
├── converted/
├── failed/
├── packages/
├── releases/staging/
├── releases/active/
├── releases/archive/
└── logs/
```

转换任务输入文件写入 `uploads/convert`，输出文件写入 `converted`。

## Python 模块目录

项目 Python 脚本位于 `python/` 目录：

```text
python/
├── convert/                     # 数据格式转换脚本（C++ subprocess 调用）
│   ├── convert_data.py          # 通用入口
│   └── <product_code>/          # 各产品专属转换脚本（可选）
├── admin/                       # 管理员工具集
│   ├── admin.py                 # 统一入口，交互式选择 TOML 配置
│   ├── _product.py              # 产品写入
│   ├── _release.py              # 版本写入
│   ├── _asset.py                # 全量包写入
│   ├── _channel.py              # 渠道 latest 指针
│   ├── _update_package.py       # 增量包写入
│   ├── _convert_rule.py         # 数据转换规则写入
│   ├── _page.py                 # 页面运维
│   └── _cleanup.py              # 清理过期临时文件
└── lib/                         # 公共库
    ├── db.py                    # SQLite 连接与读写封装
    ├── config.py                # 读取 config/app.json 配置
    ├── toml_loader.py           # TOML 加载与校验
    └── operations.py            # 操作编排器
```

管理员通过 `python/admin/admin.py` 统一入口执行 TOML 配置，不再使用单独命令行参数脚本。具体用法见 [08-运维手册/管理员操作指南.md](../08-运维手册/管理员操作指南.md)。

## Daily v1.0.0 入库记录

Daily 插件已按以下数据写入 SQLite：

| 表 | 字段 | 值 |
| --- | --- | --- |
| `products` | `code` | `Daily` |
| `products` | `icon_path` | `/data/releases/Daily/v1.0.0/icon/image.png` |
| `releases` | `version` | `v1.0.0` |
| `releases` | `data_schema_version` | `v1.0.0` |
| `releases` | `vue_path` | `/data/releases/Daily/v1.0.0/vue/DailyReleasePage.vue` |
| `release_assets` | `platform / arch / package_type` | `obsidian / any / plugin` |
| `release_assets` | `file_path` | `./data/packages/Daily/v1.0.0/Daily-v1.0.0.zip` |
| `release_channels` | `channel / is_latest` | `stable / 1` |

Daily 当前插件版本和数据版本一致，都是 `v1.0.0`，因此不需要新增 `convert_rules`。
