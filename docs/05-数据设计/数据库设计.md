# 数据库设计

数据库结构以 `migrations/002.init.sql` 为准。`Storage_SQL` 启动时打开 `config/app.json` 中的 `database_path`，空库执行初始化 SQL，已有库通过 `ensurePortfolioSchema()` 补齐首页相关表和字段。

实际文件保存在 `data/`，SQLite 保存元信息、路径、状态和任务记录。

## 表结构总览

| 表 | 用途 |
| --- | --- |
| `schema_migrations` | 结构迁移版本 |
| `products` | 产品基础信息 |
| `product_careers` | 产品职业方向 |
| `recommendations` | 首页推荐项目 |
| `site_profile` | 站点资料 |
| `future_directions` | 未来方向 |
| `releases` | 产品版本 |
| `release_assets` | 全量包 |
| `release_channels` | 渠道 latest 指针 |
| `update_packages` | 增量包或补丁包 |
| `convert_rules` | 数据结构版本转换规则 |
| `convert_tasks` | 数据转换任务 |

## schema_migrations

字段：

1. `version`
2. `applied_at`
3. `note`

首页结构迁移版本：

```text
20260606_portfolio_home
```

## products

字段：

1. `id`
2. `name`
3. `code`
4. `github_url`
5. `description`
6. `icon_path`
7. `status`
8. `created_at`
9. `updated_at`

`ProductsAction` 返回产品列表时把 `code` 映射为 `product_code`，把 `description` 映射为 `summary`。

## product_careers

字段：

1. `id`
2. `product_id`
3. `career`
4. `created_at`
5. `updated_at`

唯一约束：

```text
product_id + career
```

## recommendations

字段：

1. `id`
2. `product_id`
3. `status`
4. `sort_order`
5. `created_at`
6. `updated_at`

首页主推项目通过 `recommendations.product_id` 关联 `products.id`。

## site_profile

字段：

1. `id`
2. `site_name`
3. `subtitle`
4. `github_url`
5. `email`
6. `created_at`
7. `updated_at`

约束：

```text
id = 1
```

顶部导航和 Footer 使用 `site_profile.github_url` 与 `site_profile.email`。

## future_directions

字段：

1. `id`
2. `title`
3. `comment`
4. `icon_path`
5. `status`
6. `sort_order`
7. `created_at`
8. `updated_at`

首页只读取 `status = active` 的记录。

## releases

字段：

1. `id`
2. `product_id`
3. `version`
4. `release_note`
5. `data_schema_version`
6. `status`
7. `vue_path`
8. `published_at`
9. `created_at`
10. `updated_at`

`DocumentAction` 使用 `product_code + version` 定位版本详情。

## release_assets

字段：

1. `product_id`
2. `release_id`
3. `platform`
4. `arch`
5. `package_type`
6. `file_path`
7. `file_size`
8. `sha256`
9. `md5`
10. `status`

更新检查通过 `release_channels` 指向的 latest release 关联全量包。

## release_channels

字段：

1. `product_id`
2. `release_id`
3. `channel`
4. `platform`
5. `arch`
6. `package_type`
7. `is_latest`
8. `status`
9. `created_at`
10. `updated_at`

唯一 latest 约束：

```text
product_id + channel + platform + arch + package_type
```

## convert_rules

字段：

1. `product_id`
2. `source_data_schema_version`
3. `target_data_schema_version`
4. `script_path`
5. `cost_time`
6. `script_sha256`
7. `status`

`ConvertDataTaskAction` 使用 `product_id + source_data_schema_version + target_data_schema_version` 查找 active 规则。

## convert_tasks

字段：

1. `task_id`
2. `product_id`
3. `convert_rule_id`
4. `source_data_schema_version`
5. `target_data_schema_version`
6. `status`
7. `input_file_path`
8. `input_file_sha256`
9. `output_file_path`
10. `output_file_sha256`
11. `retry_count`
12. `created_at`
13. `updated_at`

状态：

1. `pending`
2. `running`
3. `success`
4. `failed`
5. `canceled`

## 文件目录

```text
data/
├── database/update_platform.db
├── backups/
├── uploads/convert/
├── converted/
├── failed/
├── packages/
├── releases/staging/
├── releases/active/
├── releases/archive/
└── logs/
```

转换任务输入文件写入 `uploads/convert`，输出文件写入 `converted`。

## Python 管理脚本

```text
python/admin/admin.py
python/admin/migrate_sqlite.py
python/admin/export_sqlite_json.py
python/admin/import_sqlite_json.py
```

`admin.py` 支持以下 TOML 配置块：

1. `site_profile`
2. `product`
3. `future_direction`
4. `recommendation`
5. `release`
6. `release.asset`
7. `release.channel`
8. `update_package`
9. `convert_rule`
10. `page_publish`
11. `page_offline`
12. `page_rollback`
13. `cleanup`
